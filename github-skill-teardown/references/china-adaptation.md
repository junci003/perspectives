# 国内拆改参考（写改造建议时读这份）

## 一、六个约束层

国外 skill 默认的前提，在国内逐条不成立。给改造意见时按这六层过一遍，不要只谈语言翻译。

| 层 | 国外默认 | 国内实际 | 改造难度 |
|---|---|---|---|
| 模型 | Claude / GPT 特定的指令遵循行为 | DeepSeek / Qwen / GLM / Kimi / 豆包 / 混元 | 低（SKILL.md 是语义触发，格式无关） |
| 通道 | Claude plugin marketplace / skills.sh / npx skills | WorkBuddy / Coze / 腾讯云 ADP / ClawHub | 中（形态不同，Coze 是"插件"不是 SKILL.md） |
| 合规 | 基本无约束 | 算法备案 + 模型备案 + 个保法 + 平台服务协议 | **高，不可绕过** |
| 数据/网络 | Notion / Slack / Discord / Telegram / Stripe | 飞书 / 钉钉 / 企微 / 腾讯文档 / 微信支付 | 中 |
| 语言/语料 | 英文语料的 AI 味特征 | 中文 AI 味是**完全另一套** | 高，需重做而非翻译 |
| 支付 | Sponsors / PayPal / Stripe / Buy Me a Coffee | 微信支付 / 支付宝 / 知识星球 / 小报童 | 中 |

## 三、四条红线（必须逐条检查）

### 红线 1 · 采集类（最高危）
国外热门 skill 大量做"扒平台数据"。国内实测扫到同类仓库：
- 「抖音收藏夹 → RAG 知识库（Playwright **绕过反爬**）」
- 「**Scrape** interview experiences from Xiaohongshu」
- 对标的国外样本：`competitive-ads-extractor`（扒竞品广告库）、`last30days-skill`（跨 Reddit/X/YouTube 研究）

违反平台服务协议，可能触及《数据安全法》《反不正当竞争法》。
> **改造原则：凡「采集」→ 替换为「官方 API + 用户主动授权的数据」。做不了就砍掉功能，不要留 POC。**

### 红线 2 · 平台风控规避
「多账号管理 / 自动养号 / 规避限流 / 批量发布互动」在国内平台规则下一律违规。
注意：**纯输出类 skill（改写风格、生成设计卡、出图）没有这个问题，风险集中在"发布/互动"环节。**

### 红线 3 · 付费通道
PayPal / Stripe / Buy Me a Coffee / GitHub Sponsors **国内不可用**。
- 个人：知识星球 / 小报童 / 爱发电 / 微信赞赏码
- B 端：对公账户 + 增值税发票（国内 B 端采购硬要求）

### 红线 4 · 缺少备案的对外服务
skill 若捆绑对外服务的后端，面向国内公众提供服务需**算法备案 + 模型备案**。
纯本地运行（数据不出域）可规避 —— 这正是 CoPaw、AutoClaw 主打"本地存储"的原因。

## 五、三个明确的空白位

判断依据：国外有高星样板 + 国内零竞品 + 符合"一次输出可检验"准则。

| 空白 | 国外样板 | 为什么是机会 |
|---|---|---|
| **中文 AI 味清单（zh-humanizer）** | `blader/humanizer` 50,885★（基于 Wikipedia "Signs of AI writing"） | 中文 AI 味是**另一套**：① "不是 A，而是 B" 结构 ② 首先/其次/最后 ③ 赋能/闭环/抓手/颗粒度 ④ 综上所述 / 值得注意的是 / 在当今时代 ⑤ 四字格堆砌与排比 ⑥ "作为 AI 我认为"式免责前缀。**国内自媒体/公文/教培刚需，且没人系统整理过。** |
| **中文办公场景 skill 包** | `anthropics/skills` 有 docx/pdf/pptx/slack，**零个中国办公场景** | 对标位置全空：`wecom-doc` / `feishu-bitable` / `dingtalk-approval` / `xiaohongshu-note`。官方文档齐备，**做得到**。 |
| **非编程的 meta-skill 决策树** | `addyosmani/agent-skills` 的树是纯软件生命周期 | 内容创作 / 运营 / 研究 / 教学的生命周期映射，没人做过。 |

## 六、改造时容易漏的三件事

1. **`name` 字段不能有中文。** Agent Skills 规范：name ≤64 字符，仅小写字母、数字、连字符，不能以连字符开头或结尾。中文只能放 `description` 和正文。国内作者最常踩这个坑。

2. **中文用户的追问容忍度显著低于英文用户。** 那类"连环追问几十个细节"的 skill（如 `grill-me`）会触发即弃。改成"一次最多问 3 个 + 允许跳过 + 给默认值让用户确认"。

3. **视觉/审美参照系必须整体替换，不是翻译。**
   - LLM 的英文默认审美：AI 紫渐变、居中 hero 配暗色网格、三张等宽特性卡片、泛滥玻璃拟态、Inter + slate-900
   - 国内要换成：抖音/小红书/微信小程序主流视觉语言、国潮、政务蓝、金融红（**金融场景国内是红涨绿跌，与欧美相反**）
   - 字体：Inter/Geist/Montserrat → 思源黑体 / 苹方 / HarmonyOS Sans / 阿里普惠体（阿里普惠体免费商用是明确的）
   - 图像生成通道：Gemini / Atlas Cloud / MuAPI → 豆包 Seedream / 通义万相 / 可灵 / 即梦

4. **中文 tokenizer 的压缩收益必须实测后再断言。** 英文结论（自造缩写零收益、箭头零收益）不能直接迁移——中文的压缩对象完全不同（是敬语、四字格、"首先其次最后"，不是冠词）。文言文压缩的收益在中文上**大概率省字符不省 token**，未实测前不要写进宣传。

## 七、抄什么：五件高 ROI 的事（按优先级）

| # | 抄什么 | 来源样板 | 为什么 |
|---|---|---|---|
| 1 | **description 只写触发条件，不写工作流** | superpowers | 零成本改动，避免 agent 走捷径跳过正文 |
| 2 | **meta-skill 决策树** | addyosmani/agent-skills | skill 超过 3 个就必须有，否则没人用 |
| 3 | **输出「配置卡」而非「建议」** | ui-ux-pro-max / taste-skill | 直接决定用户能不能用起来 |
| 4 | **每个 skill 写「失效条件」** | karpathy-guidelines / taste-skill | 建立可信度最便宜的方式 |
| 5 | **共享语言文件（CONTEXT.md）** | mattpocock/skills | 一次建立、每个会话都省，且提升输出一致性 |
