# Skill Ops Team

把技能从草稿送到上架：拆解生态、发布到 ClawHub、修复本地环境、归档会话。

## 类型

Team 型（多角色协作团队，4 人）

## 团队构成

| 名字 | 职业 | 职责 |
|---|---|---|
| 齐上架 | 技能发行总监 | 编排调度、发行决策、最终汇编 |
| 甄透彻 | 生态拆解师 | 竞争格局、正文判重、热度与启用率区分 |
| 尚加推 | 发布工程师 | 发布前审查、description 改写、真发与核对 |
| 修得通 | 环境修复工程师 | 代理 / npm / WSL / 重装 / 会话归档 |

## 预设 Workflow

- **W1 值得发吗**：只跑摸底，K 结论
- **W2 帮我发布**：摸底 → 准备 → 环境托底（并行）→ 执行核对 → 汇编
- **W3 发布失败了**：先排环境，再怀疑参数
- **W4 沉淀一下**：归档分支

## 使用示例

- 帮我把这个技能发出去，先看这个赛道有没有人做过
- 这个赛道还是空白位吗，还是有人做过没做成？给我证据
- 发布失败了，报错看不懂，帮我判断是环境问题还是参数问题
