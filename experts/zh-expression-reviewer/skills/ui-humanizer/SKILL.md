# UI 去 AI 味

## 一句话原理

AI 生成的界面不是「不好看」，是**没有任何一处做过取舍**。

每个决定都取了对最多人最安全的那个值：最保险的紫、最保险的圆角、最保险的居中。所以 AI 味的成因和文本一样——**它太平均**。

由此推出两条，这两条决定了后面所有做法：

1. **把紫色换成蓝色不解决任何问题。** 那只是换了一个同样平均的蓝。任何「换一批默认值」的修法，本质都是把 A 平均换成 B 平均。
2. **唯一的真出路是让界面里出现「只有你会做的决定」。** 判据非常硬：**如果你把这个界面上的所有文案删掉，还剩什么在说明它是这个产品而不是任意一个产品？**

> 与文字版的区别：`zh-humanizer` 处理语义层的平均；这里处理**视觉与交互层**的平均。两者共享同一个成因，但判据、手段、交付物完全不同。

---

## 一、三类硬指纹（可以自动检测）

硬指纹的定义：**机器能数出来，且数出来的数字本身就有意义。**

### 1.1 AI 默认色板

模型和模板最常引用的色值，几乎全在 Tailwind 默认色板的 indigo / violet 区间：

| 色值 | 名称 | 出现位置 |
|---|---|---|
| `#6366f1` | indigo-500 | 主按钮、链接、焦点环 |
| `#4f46e5` | indigo-600 | 按钮 hover、标题强调 |
| `#8b5cf6` | violet-500 | 渐变起点 |
| `#a855f7` | purple-500 | 渐变终点、徽标 |
| `#7c3aed` | violet-600 | 卡片边框、图标 |
| `#818cf8` | indigo-400 | 次要文字、图表 |
| `#ec4899` | pink-500 | 「彩虹渐变」的常见终点 |

配套的渐变签名：`from-indigo-500 to-purple-600`、`from-purple-500 to-pink-500`、`bg-gradient-to-r from-* via-* to-*` 三色及以上。

**判定要点：不看有没有，看密度和分布。** 一个 `#6366f1` 完全正常；一屏里主按钮、链接、图标、图表、焦点环、徽标全落在同一色相区间，才是指纹。

### 1.2 Emoji 当图标

出现在**图标应该在的位置**才算指纹：

- 按钮内（`<button>🚀 开始使用</button>`）、导航项、卡片标题、状态徽标、空状态、表头
- 高频清单：📊 📈 📉 📝 💾 🗂 🤖 ✨ 🚀 ⚡ 🔥 🎯 💡 🔒 ✅ ❌ ⚠️ 👋 🎉

**不算指纹的位置**：正文语气、社交分享文案、用户自己输入的内容、真正的表情场景（聊天/评论）。

判据一句话：**这个 emoji 是在承担「图标」的职能，还是在承担「表情」的职能？** 承担图标职能的就是替代品，因为它省掉了「选一套图标体系」这个决定。

### 1.3 技术信息泄漏到用户界面

用户看到的句子是写给程序员看的：

- `alert(e.message)` / `alert(error)` —— 直接把 `Failed to fetch`、`NetworkError when attempting to fetch resource.` 甩到用户脸上
- 渲染原始错误：`Error: `、`TypeError:`、堆栈片段、`[object Object]`、`undefined`、`null`
- 裸露状态码与协议词：`500`、`403`、`CORS`、`timeout of 10000ms exceeded`
- 占位残留：`TODO`、`Lorem ipsum`、`test@example.com`、`User Name`

判据：**把这句报错念给一个不用电脑的家人听，他能知道下一步该干什么吗？**

## 二、三类软指纹（需要判断，别机械套）

### 2.1 几何上的无取舍

- 所有容器都是 `rounded-2xl` 或 `16px`，没有任何一处例外
- 所有卡片同高同宽、`shadow-lg` 无差别铺开
- 边框/分割线在本来可以用留白的地方全铺一遍
- 间距都是 8 的倍数（这本身是对的），但**节奏没有变化**——该紧的地方不紧、该松的地方不松

### 2.2 布局的默认答案

| 场景 | AI 的默认答案 |
|---|---|
| 落地页 | 居中大标题 + 副标题 + 双按钮 → 三张等宽 feature 卡 → 客户 logo 墙 → CTA 条 |
| 后台 | 左侧固定侧栏 + 顶部搜索 + 四张同款 KPI 卡 + 一张大表格 |
| 空状态 | 一个大号灰色 emoji + 「暂无数据」 |
| 定价页 | 三档并排，中间那档加个「推荐」角标 |
| 关于页 | 时间轴 + 三张团队头像卡 |

**这些结构不是错，是「没有根据这个产品做过选择」。** 判断方法：问一句「这个产品的核心动作是什么？」——如果默认布局里找不到它，就是软指纹。

### 2.3 文案的占位感

`Welcome to X` / `Get Started` / `Learn More` / `Your All-in-One Solution` / `Supercharge your workflow`；中文侧：`赋能` / `一站式` / `革新` / `开箱即用` / `让 X 更简单`。

判据：这段话换到任何一个同类产品上是否照样成立？成立＝占位。

## 三、检测怎么做

### 有代码

```bash
PY="${PYTHON:-python3}"
"$PY" "<skill目录>/scripts/scan_ui_ai_tells.py" <项目目录> --json report.json
```

输出：三类硬指纹的命中明细 + 各色相密度 + 总分（0–100，越高越 AI）。`--gate --threshold 45` 可作 CI 拦截。

### 只有截图 / 线上页面

按 `references/visual-tells.md` 的核对表人工过一遍。人工过的时候守一条纪律：**数数量，不判有无**（见 1.1）。

### 两类都要做的定性一步

回答三个问题，写在诊断开头：

1. 这个界面的**核心动作**在哪儿？一眼能看到吗？
2. 有哪一处决定是**这个产品特有的**？没有的话，这就是主要问题。
3. 关掉配色看黑白稿，结构还站得住吗？

## 四、修复方向（按性价比排序）

完整的替换映射（含替代色板选法、图标体系、报错包装代码）见 `references/fix-mapping.md`。

1. **先删，再加。** 把圆角、阴影、边框、装饰渐变各砍掉一半，看结构是否还成立。多数 AI 界面的问题是「装饰在替结构说话」。
2. **色不从色板来，从业务来。** 不要「换一个更好看的紫」，要问：这个产品所在行业的实物/场景里，主色是什么？色相由业务定，明度饱和度再统一。
3. **图标成体系。** 选一套线性图标（同一 stroke-width、同一圆角端点），把承担图标职能的 emoji 全部替换。参考实现见 `references/fix-mapping.md`。
4. **报错说人话。** 用统一的 `friendlyError()` 包一层：发生了什么 + 你可以做什么 + 一个可追踪的 id。
5. **文案具体化。** 把「我们提供 X」换成「你在 Y 情况下会怎样」。每一句都要能通过「换到别的产品是否成立」的测试。
6. **加一处非默认决定。** 一个只有这个产品会做的交互、一句只有你们会说的话、一个行业特有的信息结构。这一条是所有修法里唯一真正治本的。

## 五、强度分档

| 档 | 范围 | 适用 |
|---|---|---|
| **L1 微调** | 只换硬指纹：色值、emoji、报错文案 | 时间紧、要保留现有视觉框架、企业内已有设计规范 |
| **L2 重构视觉层** | 重排视觉重量、统一图标与圆角体系、重写文案、收敛色相 | 默认档 |
| **L3 改信息架构** | 默认布局本身是 AI 味来源（hero+3 卡 / KPI×4），需要重做结构 | 落地页、首页、核心流程页 |

**先声明档位再动手。** 没声明档位就改，会被理解成「你把我设计全推翻了」。

## 六、失效条件（什么时候别动）

1. **已有成熟设计系统** → 只查偏离 token 的地方，不要用「AI 味」重新定义风格。
2. **品牌色本身就是紫色系** → 色相不是证据，重新找判据（看布局与文案的默认度）。
3. **企业内部工具 / 一次性 demo** → 改这个 ROI 极低，除非用户明确说「要给外部看」。
4. **无障碍已达标** → 不要为了「去 AI 味」把对比度改坏。低对比度不是高级，是失效。
5. **用户只说「不好看」** → 那是审美需求，不是 AI 味问题。先问清「你是觉得它像 AI 做的，还是就是不喜欢这个风格」。
6. **不做检测规避** → 本 skill 是**改善设计**，不是把界面伪装成「人类设计」以骗过某个检测器。申明这一点，并拒绝「帮我过 X 检测」这类请求。
7. **不要用「去 AI 味」否定现代感** → 扁平、克制、大留白本身没有错。错的是无取舍，不是风格。

## 七、验证判据

改完逐条自查，**任一不过就是没改完**：

1. **色相收敛**：一屏内主色 ≤ 2 个色相（中性色不计）。
2. **图标同构**：承担图标职能的 emoji 数为 0；所有图标来自同一套、同一 stroke。
3. **零技术泄漏**：`grep -E "undefined|NetworkError|Failed to fetch|alert\(|\[object Object\]"` 无命中（`console` 与开发日志不算）。
4. **主次可见**：截图缩到 30% 看，仍能一眼指出一个视觉焦点。
5. **有非默认决定**：能指出至少一处只有这个产品会做的选择。
6. **可证伪**：把首屏给一个没看过的人看 3 秒，问「这是做什么的」——答不出来，说明它只是「平均的好看」。

**加分项**：把装饰全部删掉，结构仍然站得住。

## 八、反模式表（八种改歪的样子）

| 反模式 | 长什么样 | 为什么是错的 |
|---|---|---|
| **换色当修复** | `#6366f1` → `#3b82f6` | 换了一个同样平均的值，无取舍的问题一点没动 |
| **加动效掩盖** | 布局照旧，全部元素加 `animate-fade-in-up` | 装饰替结构说话，AI 味变成「更吵的 AI 味」 |
| **去 AI 味做成变丑** | 极低对比度、怪字体、故意错位 | 「不平均」≠「难看」，特异性要有依据 |
| **无差别去圆角** | 全站 `rounded-none` | 只是把一种均匀换成另一种均匀 |
| **换一批 emoji** | 📊 → 🟣 | 体系问题没解，只是换了符号 |
| **抄一个知名产品的皮** | 把界面做成 Linear / Notion 的样子 | 你的「非默认决定」还是别人做的 |
| **只改首屏** | 首页精修，跳转后全是默认模板 | 不一致本身就是 AI 味（模板拼接感） |
| **把无取舍当成风格** | 声称「极简主义」但删完什么都不剩 | 极简是取舍到极致，不是没有取舍 |

**通用判据：如果这次改版没有否掉任何一个原本存在的视觉决定，那它不是改版，是重刷了一遍。**

## 九、交付形态

固定四段，缺一不可：

1. **诊断** —— 硬指纹命中明细（带数量）+ 三个定性问题的答案 + 判定的档位
2. **修复** —— 按 L1/L2/L3 改后的代码 / 规范 / 对照表
3. **修改说明** —— 每条改动的理由，一句话一条
4. **需补充** —— 缺品牌信息时明确标注 `[需补充：品牌主色 / 行业 / 目标用户]`，**不许编造品牌方向**

---

## 十、已知边界

- **不做审美背书**：能判断「有没有取舍」，不能替你判断「哪种风格更好卖」。
- **不检测「是否 AI 生成」**：检测器会误判人类作品，本 skill 只做**设计质量**判断，不参与军备竞赛。
- **对截图的能力有限**：脚本只吃代码；纯截图靠人工核对表，会漏掉动效与交互层的问题。
- **不覆盖品牌层**：logo、字体授权、摄影风格不在范围内。
