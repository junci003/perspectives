# 视觉指纹库（核对表）

> 用法：**数数量，不判有无。** 逐项记下命中次数与分布，再判断是不是问题。
> 这一份是人工核对用的；脚本能自动覆盖的项标了 `[auto]`。

---

## A. 配色

### A1. AI 默认色板 `[auto]`

Tailwind 默认色板中被引用频率最高的区间。命中即计数，重点看**是否集中在同一色相**。

| Hex | Tailwind 名 | 常见用途 |
|---|---|---|
| `#6366f1` | indigo-500 | 主按钮、链接、focus ring |
| `#4f46e5` | indigo-600 | hover、标题强调 |
| `#4338ca` | indigo-700 | 深色态 |
| `#818cf8` | indigo-400 | 次要文字、图表序列 |
| `#8b5cf6` | violet-500 | 渐变起点、tag |
| `#7c3aed` | violet-600 | 边框、图标 |
| `#a855f7` | purple-500 | 渐变终点、badge |
| `#c084fc` | purple-400 | 浅色态 |
| `#ec4899` | pink-500 | 彩虹渐变终点 |
| `#f472b6` | pink-400 | 同上 |
| `#06b6d4` | cyan-500 | 与上列搭配的次要色 |
| `#14b8a6` | teal-500 | 「清新科技感」配色 |

**判据**：单点命中 ≤2 次可忽略；同一屏内 ≥4 个不同色值落在 indigo→violet→purple→pink 这条链上 → 命中。

### A2. 渐变签名 `[auto]`

- 两色渐变：`from-indigo-500 to-purple-600`、`from-purple-500 to-pink-500`、`from-blue-500 to-purple-500`
- 三色及以上：`from-* via-* to-*` —— 三色渐变几乎只在 AI 生成和模板里出现
- 彩虹渐变：色相差 >120° 的连续过渡（如 `from-red-500 via-yellow-500 to-blue-500`）
- CSS 直写：`linear-gradient(135deg, #6366f1 0%, #a855f7 100%)` —— **135deg 是高频共现角度**

### A3. 暗色模式「赛博感」签名

`#0f172a` / `#1e1b4b` / `#18181b` 作背景 + 紫青双色发光边框 + `blur` 光晕。不是错，但与 A1 同时出现时强度叠加。

### A4. 语义色被拿来当装饰

`red / green / amber` 出现在与状态无关的位置（例如把 `#ef4444` 用作强调色而不是错误色）。会让界面语义失真。

## B. 图标

### B1. Emoji 承担图标职能 `[auto]`

**在以下位置出现即判定为指纹**：

| 位置 | 例子 |
|---|---|
| `<button>` 内 | `🚀 立即开始`、`✨ 生成` |
| 导航项 / 菜单项 | `📊 数据看板`、`🗂 文件管理` |
| 卡片标题前缀 | `⚡ 高性能` |
| 状态 / 徽标 | `✅ 已同步`、`⚠️ 警告` |
| 空状态 | 大号灰色 emoji + 「暂无数据」 |
| 表头 / 列表项首 | `🕒 创建时间` |
| 页面 H1 前缀 | `👋 你好，欢迎回来` |
| README / 手机号 / 邮箱占位 | `📧 test@example.com` |

高频 emoji 清单（按出现频率）：
`📊 📈 📉 📝 💾 🗂 📁 🤖 ✨ 🚀 ⚡ 🔥 🎯 💡 🔒 ✅ ❌ ⚠️ 🛡 ⭐ 🌟 🧠 💬 📦 🎨 🔔`

**不算指纹**：用户生成内容里的 emoji、评论区、聊天正文、社交媒体分享文案、真正的表情语气（`😅`）。

### B2. 图标体系不一致 `[auto 部分]`

- 同一屏里混用实心 / 线性两套图标
- stroke-width 不统一（1.5 和 2 混用）
- 图标与文字基线不齐、尺寸不统一（16/18/20 混用）
- 方形 icon button 的圆角与卡片圆角不是同一套 token

## C. 文案与错误

### C1. 技术信息泄漏 `[auto]`

`[auto]` 部分（可 grep）：

```
undefined | null | NaN | [object Object]
Error: | TypeError | ReferenceError
Failed to fetch | NetworkError | net::ERR_ | CORS
alert( | .message 直接渲染
timeout of \d+ms exceeded | status code 4\d\d | 5\d\d
```

需要人工判断的部分：

- 错误提示没有「下一步能做什么」
- 英文报错直接出现在中文界面里
- 同一类错误在不同位置文案风格不一致
- 用「系统错误，请稍后重试」覆盖了所有情况（另一种极端：无信息）

### C2. 占位文案 `[auto 部分]`

英文：`Welcome to`、`Get Started`、`Learn More`、`Your All-in-One Solution`、`Supercharge`、`Seamlessly`、`Effortlessly`、`Next-Generation`、`Cutting-Edge`、`Lorem ipsum`、`TODO`
中文：`赋能`、`一站式`、`闭环`、`抓手`、`革新`、`开箱即用`、`让 X 更简单`、`为 X 而生`、`重新定义 X`

**测试**：把这句话换到同类另一个产品上，是否照样成立？成立＝占位。

## D. 几何与层

### D1. 圆角 `[auto]`

- 全站只有一档圆角（全 `rounded-2xl` / 全 `16px`）
- 按钮、卡片、输入框、头像、徽标全部同圆角
- 圆角 >24px 用在大面积容器上（「大软蛋」感）

### D2. 阴影与边框 `[auto 部分]`

- `shadow-lg` / `shadow-xl` 无差别铺在所有卡片
- 阴影与边框同时存在（两套分层语言并用）
- 用彩色阴影（`shadow-indigo-500/50`）
- 发光边框（`ring-2 ring-purple-500/50`）

### D3. 视觉重量 `[人工]`

- 主次不分：所有区块字号、字重、留白几乎同一档
- 缩到 30% 看不清焦点在哪

## E. 布局模板 `[人工]`

| 页面 | 默认模板 |
|---|---|
| 落地页 | 居中 H1 + 副标题 + 双 CTA → 3 张等宽 feature → logo 墙 → CTA 条 → footer 四列 |
| 后台 | 左侧栏 + 顶栏搜索 + 4 张同款 KPI + 一张大表 |
| 定价 | 三档并排，中间高亮 + 「推荐」角标 |
| 空状态 | 灰色大 emoji + 「暂无数据」+ 一个主按钮 |
| 关于 | 时间轴 + 3 张团队卡 |
| 设置 | 左侧分栏 + 右侧表单，每行「标签 + 输入 + 说明」 |
| AI 产品自身 | 大输入框居中 + 「试试问：」示例 chips + 结果区灰底块 |

**判断方法**：问「这个产品的核心动作是什么？」——在默认布局里找得到它吗？找不到就是软指纹。

---

## F. 动效 `[人工]`

- 所有元素同一款 `fade-in-up`，延迟按索引均匀递增（0/100/200/300ms）
- hover 全部是 `scale-105` + `transition-all`
- 加载态一律是三个点 `...` 或紫色 spinner
- 数字滚动动画无差别使用
- 页面切换用同一个 fade

---

## G. 内容与真实性 `[人工]`

- 数据是 `1,234` / `99.9%` / `+42%` 这类明显编造的整数
- 图表曲线平滑得像示意图，没有真实噪声
- 用户头像是字母缩写圆形色块、logo 墙是灰阶占位方块
- `test@example.com`、`张三`、`示例公司` 当真实内容展示
- 无来源的引用、无出处的统计
