# 修复映射表

> 原则：**下面所有「替换」都是起点，不是答案。** 任何一条照抄的替换，都会把「平均的紫」变成「平均的蓝」。
> 判据始终是那一句：改完之后，这个界面上有没有出现一处只有这个产品会做的决定？

---

## 1. 配色：不换色，改选色的方法

### 别这么做

```
#6366f1 → #3b82f6      ✗ 只是换了一个同样平均的值
#6366f1 → #000000      ✗ 去 AI 味做成变丑
#6366f1 → 品牌色（如果品牌色本身没定）  ✗ 把问题推给下一个人
```

### 三种能用来自证的取色法

**① 业务实物取色（最稳）**
去产品对应的现实场景里取色：包装、行业标准标识、常用物料的典型色、目标用户所处环境的常见色。取到的色相有出处，能解释为什么是它。

**② 约束法**
如果确实没有来源，用一个硬约束把选择逼出来：**整站只允许一个非中性色相**。一旦只剩一个色相，饱和度与明度就必须按层级自己排——这一步会自动消灭「彩虹渐变」和「一屏七个紫」。

**③ 反向法**
看三个直接竞品，列出它们的色相 → 你**避开其中重复出现的那个**。这是最低成本的差异化，也天然通过「非默认」测试。

### 中性层必须先定

AI 界面的一个隐蔽问题是中性色也在默认值上（`#64748b` slate 系全家桶、`#f3f4f6` gray-100 铺底）。
中性色梯度取 5 档即可，且**提前定好用途**：

| 档 | 用途 | 典型明度 |
|---|---|---|
| bg | 页面底 | 98–100% |
| surface | 卡片 | 100%（暗色下 12–16%） |
| border | 分割 | 90% |
| text-secondary | 说明文字 | 45–55% |
| text-primary | 正文 | 8–15% |

定了用途，就不需要每次都想「这里用 gray-200 还是 slate-200」——**每一次临时选色都是一次平均化的机会**。

### 渐变怎么处理

- 三色及以上渐变：直接删。
- 两色渐变：只保留在**有功能含义**的地方（进度、热力、数据可视化），装饰性渐变删除。
- 如果品牌确实需要渐变：色相差压到 30° 以内（同色相内明度变化），避免跨越色相的「彩虹感」。

```css
/* ✗ 彩虹感 */
background: linear-gradient(135deg, #6366f1 0%, #a855f7 100%);

/* ✓ 同色相内变化，无彩虹感 */
background: linear-gradient(135deg, #1e3a5f 0%, #2d5a87 100%);
```

## 2. Emoji → 图标体系

### 选一套，只用一套

| 体系 | 特点 | 适合 |
|---|---|---|
| Lucide | 线性、2px stroke、圆端点、1400+ | 通用默认，Web/移动端 |
| Heroicons | 线性+实心两套、MIT | Tailwind 项目 |
| Phosphor | 多字重、风格选择多 | 需要字重分层 |
| Radix Icons | 15×15、极简 | 界面密集型后台 |

选定后写进规范：**同一页面内只用一套、只用同一 stroke-width、只用同一尺寸档（16/20/24）**。

### 常见替换对照（Lucide 为例）

| emoji | 语义 | Lucide 名 |
|---|---|---|
| 📊 📈 📉 | 数据 / 趋势 | `bar-chart-3` / `trending-up` / `trending-down` |
| 📝 ✏️ | 编辑 | `pencil-line` |
| 💾 | 保存 | `save` |
| 🗂 📁 | 文件 / 目录 | `folder` / `folder-tree` |
| 🤖 | AI / 机器人 | `bot` |
| ✨ | 生成 / 优化 | `sparkles` |
| 🚀 | 发布 / 启动 | `rocket` |
| ⚡ | 性能 | `zap` |
| 🎯 | 目标 | `target` |
| 💡 | 提示 | `lightbulb` |
| 🔒 🛡 | 安全 | `lock` / `shield-check` |
| ✅ ❌ ⚠️ | 状态 | `circle-check` / `circle-x` / `triangle-alert` |
| 👋 | 欢迎 | `hand`（或干脆去掉） |
| 🔔 | 通知 | `bell` |
| 📦 | 包 / 版本 | `package` |
| 🎨 | 主题 | `palette` |
| 🧠 | 模型 | `brain`（若无则 `cpu`） |

### 代码形态

```jsx
// ✗ emoji 承担图标职能
<button>🚀 立即部署</button>

// ✓ 图标组件，尺寸与 stroke 统一
import { Rocket } from "lucide-react";
<button className="btn">
  <Rocket size={16} strokeWidth={2} aria-hidden="true" />
  立即部署
</button>
```

三个容易漏的点：

1. **`aria-hidden="true"`** —— 装饰性图标必须对读屏隐藏，否则会念出图标名。
2. **尺寸对齐** —— 图标与文字的视觉基线对齐（通常靠 `display:inline-flex; align-items:center; gap:*`）。
3. **空状态** —— 不要用大号灰色 emoji。用线性图标（`inbox` / `search-x`）或直接用一句话 + 一个主按钮。

## 3. 报错说人话

### 症状

```js
// ✗ 用户看到英文技术信息
try { await submit(); }
catch (e) { alert(e.message); }   // → "Failed to fetch"
```

```js
// ✗ 更糟：把对象直接渲染
{error && <div>{error}</div>}      // → "[object Object]"
```

### 统一包装

```js
// lib/friendlyError.js
const MAP = [
  [/Failed to fetch|NetworkError|net::ERR_/i, {
    msg: "网络连接不上，内容没有保存",
    act: "检查网络后重试；如果一直不行，把下面的编号发给我们",
  }],
  [/timeout/i, {
    msg: "服务器响应太慢，这次操作没完成",
    act: "稍等一分钟再试一次",
  }],
  [/\b(401|403)\b/, {
    msg: "你没有这项操作的权限",
    act: "换一个有权限的账号，或联系管理员开通",
  }],
  [/\b(500|502|503|504)\b/, {
    msg: "服务器出问题了，不是你的操作有误",
    act: "等几分钟重试；持续出现请把编号发给我们",
  }],
];

export function friendlyError(e, opId = Math.random().toString(36).slice(2, 8)) {
  const raw = String(e?.message ?? e ?? "");
  const hit = MAP.find(([re]) => re.test(raw));
  // 开发环境保留原始信息，生产环境只给人话
  if (import.meta.env.DEV) console.error("[friendlyError]", opId, raw);
  return hit
    ? { ...hit[1], id: opId }
    : { msg: "操作没有完成，请重试", act: "若反复出现，请把编号发给我们", id: opId };
}
```

统一渲染：

```jsx
function ErrorToast({ error }) {
  if (!error) return null;
  const { msg, act, id } = friendlyError(error);
  return (
    <div role="alert" className="toast toast--error">
      <strong>{msg}</strong>
      <p>{act}</p>
      <code className="toast__id">{id}</code>
    </div>
  );
}
```

### 文案公式

`发生了什么` + `不是你的错（如属实）` + `你可以做什么` + `可追踪编号`

四条都写全，才算说人话。三个常见变形：

| ✗ | 问题 | ✓ |
|---|---|---|
| 系统错误，请稍后重试 | 无信息，用户不知道该不该等 | 服务器出问题了，等 2 分钟重试；持续出现请把编号 4f2a 发给我们 |
| Failed to fetch | 英文 + 无动作 | 网络断了，内容没保存。检查网络后重试 |
| 请求参数错误 | 把内部词汇暴露给用户 | 有两项没填对，已在表单上标出 |

## 4. 几何收敛（圆角 / 阴影 / 边框）

### 圆角：最多三档，且各有用处

```
--radius-sm: 6px    输入框、按钮、徽标
--radius-md: 12px   卡片、弹窗
--radius-lg: 20px   仅用于整块面板，全站不超过 2 处
```

规则：

- **大面积容器不要用大圆角**（「大软蛋」感的主因）。
- 嵌套时内层圆角 = 外层 − 内边距，否则视觉会「打架」。
- 全站 `rounded-full` 只留给头像、状态点、pill 标签。

### 阴影：用层级，不用装饰

```
--shadow-1: 0 1px 2px rgba(0,0,0,.06)        静态卡片
--shadow-2: 0 4px 12px rgba(0,0,0,.08)       悬浮、下拉
--shadow-3: 0 16px 40px rgba(0,0,0,.12)      弹窗、抽屉（全站仅此一处）
```

规则：

- **阴影和边框不要同时用于同一层**（两套分层语言并用会显得脏）。选一套。
- 彩色阴影与发光边框直接删。
- 同一层级的卡片，阴影必须一致；不同层级必须不同——「无差别 `shadow-lg` 铺满」就是 AI 味。

### 视觉重量重排（这一步比配色重要）

1. 截图转灰度。
2. 眯眼看：**第一个跳出来的是什么？** 如果跳出来的是装饰，说明结构没在说话。
3. 把「次级」的边界降低一档（去掉边框、减小字重、降一档明度），腾出的对比度留给主内容。
4. 缩到 30% 复查：仍能指出一个焦点才算过。

## 5. 文案具体化

| ✗ 占位 | 问题 | ✓ 做法 |
|---|---|---|
| Welcome to 平台名 | 换任何产品都成立 | 直接说这个产品能让用户做成什么事 |
| Get Started / 立即开始 | 没说开始干什么 | 动词 + 对象：导入账单 / 生成周报 |
| Supercharge your workflow | 无信息量的形容 | 具体到秒/次数/步骤：把对账从 40 分钟压到 3 分钟 |
| 一站式解决方案 | 体制话术 | 列出恰好覆盖的环节，并说明不覆盖什么 |
| 暂无数据 | 用户不知道下一步 | 「还没有项目 — 点这里新建第一个」 |
| 操作成功 | 没确认结果落在哪 | 「已发布到线上，链接已复制」 |

**通用规则**：每个按钮的文案应该是**它会做的事**，而不是它的情绪（「开始」「了解更多」「立即体验」全是情绪）。

## 6. 找「那一处非默认决定」

这是唯一真正治本的一步。做法是回答五个问题，答案里只要有**一个**能落到界面上，就算找到了：

1. 这个产品的用户，在打开它之前**刚做完什么**？把那件事的痕迹留在界面上。
2. 用户最怕的是什么？把这个恐惧的**反向信号**做成可见元素。
3. 这个行业有哪些**外人不知道但内行一眼懂**的信息？把它做成默认可见。
4. 哪一步可以做到**别人做不到的快**？把那一步的耗时直接显示出来。
5. 有哪句话是**只有你们会说的**（带着具体的数字、客户名、事故经历）？放在首屏。

落到具体形态通常是这几种之一：

- 一个非默认的默认值（别人都让你选，你替用户先选好）
- 一个信息结构的重排（别人按时间，你按金额 / 按风险）
- 一句带具体数字的说明（别人写「更快」，你写「平均 3 秒」）
- 一个可见的取舍声明（明确写出「我们不做什么」）

## 7. 修改说明怎么写

每条改动一句话，格式固定：

```
- [文件:行] 原值 → 新值 ｜ 理由：______ ｜ 档位：L1/L2/L3
```

例：

```
- [src/components/Hero.tsx:24] bg-gradient-to-r from-indigo-500 to-purple-600 → 单色 #1e3a5f ｜ 理由：三色相跨度的装饰渐变，无功能含义 ｜ L1
- [src/App.tsx:88] alert(e.message) → friendlyError(e) ｜ 理由：英文技术信息直接暴露给用户 ｜ L1
- [src/pages/Dashboard.tsx 全页] 4 张等宽 KPI 卡 → 1 个主指标 + 3 个次级 ｜ 理由：默认布局未体现「本月最重要的一个数字」 ｜ L3
```
