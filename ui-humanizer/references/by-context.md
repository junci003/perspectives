# 按场景：AI 味在不同界面上的形态与优先级

> 同一套指纹在不同场景里权重完全不同。**落地页的三色渐变是致命的，数据可视化里的渐变是正常的。**
> 先定场景，再定档位。

---

## 1. 落地页 / 官网首页

**AI 味的重灾区**，因为默认模板最成熟（模型见过的样本最多）。

| 表现 | 权重 |
|---|---|
| 居中 H1 + 副标题 + 双 CTA 的默认骨架 | 高 |
| 3 张等宽 feature 卡，图标全是彩色圆底 + 线性图标 | 高 |
| 三色渐变主视觉、渐变按钮 | 高 |
| 「Welcome to」「Supercharge」类占位文案 | 高 |
| logo 墙是灰阶占位方块 | 中 |
| 客户证言是「张三 · 某公司」 | 中 |
| 数字编造（99.9% / +42%） | 高（涉及可信度） |

**判据重点**：首屏 5 秒内能否回答「这是做什么的、给谁用」。答不出来，前面的视觉问题都不用修。

**优先级**：
1. L3 — 换掉默认骨架：把核心动作前置，或在首屏放一个**只有这个产品有的东西**（真实截图、真实数字、真实客户的一句话）
2. L2 — 文案具体化（全部占位句清掉）
3. L1 — 色板收敛、删装饰渐变

**别动**：如果这是 B 端产品，不要为了「有特色」牺牲信息密度。落地页的第一职能是让人看懂。

---

## 2. 后台管理 / B 端控制台

AI 味表现更隐蔽，且**危害更大**（用户每天要看）。

| 表现 | 权重 |
|---|---|
| 四张同款 KPI 卡，数字都是「1,234」形 | 高 |
| 左侧固定侧栏 + 顶栏搜索的默认三件套 | 中（行业已趋同，不算致命） |
| 表格里 12 列全等宽，无优先级 | 高 |
| 状态全靠颜色，无文字 | 高（无障碍问题） |
| 空状态是大 emoji + 「暂无数据」 | 中 |
| 表单每行「标签 + 输入 + 说明」机械排布 | 低（这确实是最优解之一） |
| 删除操作只有 `confirm()` | 高（真实风险） |

**判据重点**：**这个界面替用户做过哪些取舍？** B 端的价值恰恰来自取舍——默认时间范围、默认排序、默认隐藏的列、危险操作的二次确认。全都留给用户选，就是把决策成本转嫁出去。

**优先级**：
1. L2 — 给每张表/每个看板定默认视图（默认时间、默认排序、默认列）
2. L2 — 一句话说明每个数字的口径（「这里的 GMV 含退款」），口径说明是 B 端最缺的东西
3. L1 — 状态色 + 文字双写、危险操作确认文案重写
4. L1 — 色板收敛（后台最容易一屏七种颜色）

**别动**：别为了「有设计感」降低信息密度或加大留白——后台用户是熟练工，密度是效率。

## 3. 移动端 / 小程序

| 表现 | 权重 |
|---|---|
| emoji 当 tabbar / 导航图标 | 高（移动端图标体系一旦乱，整App廉价） |
| 紫色渐变按钮 + 大圆角卡 | 高 |
| 安全区、键盘弹起、下拉刷新等**平台习惯**没处理 | 高（比视觉更影响「像不像正经产品」） |
| 加载态是三个点 | 中 |
| 触控热区 <44px | 高（可用性） |

**判据重点**：**跟随平台规范的程度**。移动端用户对系统惯例极度敏感——一个不跟手、不跟系统返回手势的界面，无论配色多好都「像 demo」。

**优先级**：
1. L2 — 图标体系统一（tabbar 必须换成矢量图标）
2. L2 — 补齐平台习惯：安全区、返回手势、键盘避让、下拉刷新、点击态
3. L1 — 色板与圆角收敛

**别动**：不要为了差异化打破平台惯例（自定义返回手势、非标准 tabbar 位置），成本远大于收益。

## 4. 作品集 / 个人站

| 表现 | 权重 |
|---|---|
| 深色 + 紫青发光 + 玻璃拟态 | 高（这是 2023 年后最强的「AI 感」组合） |
| 首屏大标题 + 向下箭头 | 中 |
| 滚动全部元素 `fade-in-up` | 高 |
| 「I'm a passionate developer」类文案 | 高 |

**判据重点**：**有没有真实的作品细节。** 作品集的全部价值来自具体：具体项目、具体职责、具体数字、具体失败。文案越通用越致命。

**优先级**：
1. L2 — 文案换成具体的项目细节（这个项目解决什么问题、你做了什么、结果如何）
2. L1 — 删掉霓虹发光与玻璃拟态，回到能读的清白底或纯深色
3. L1 — 动效收敛：只保留 1–2 处，且服务于阅读节奏

**别动**：不要为了「与众不同」用怪字体和非标准导航。作品集要让人 30 秒内找到联系方式。

## 5. AI 产品自身的界面

**最容易 AI 味的一类**，因为它就是用 AI 生成、且照着 AI 产品的样子生成的。

| 表现 | 权重 |
|---|---|
| 「大输入框居中 + 试试问：示例 chips」的通用壳 | 高 |
| 回复区是灰底块、无来源、无引用 | 高（可信度问题） |
| 生成中是一个紫色 spinner / 三个点 | 中 |
| 模型名与技术术语直接暴露（`gpt-4o-mini`、`temperature=0.7`） | 高 |
| 无边界声明（不说它做不到什么） | 高 |

**判据重点**：**不确定性的可视化**。AI 产品的核心体验差异在于「怎么让用户知道它有多确定」。全部输出长得一样确定，是这类界面最大的 AI 味，也是最大的产品缺陷。

**优先级**：
1. L3 — 把「来源/依据」变成一等公民（引用、原文片段、置信度、生成耗时）
2. L2 — 区分「确定输出」与「需要用户确认的输出」的视觉与交互
3. L1 — 技术术语从界面撤到设置里；加载态换成阶段性提示（「正在检索…」「正在核对…」）

**别动**：不要在界面上写「AI 驱动」「Powered by AI」——这是背景信息，不是卖点。

## 6. 文档站 / 帮助中心

| 表现 | 权重 |
|---|---|
| 左侧目录 + 右侧内容 + 顶栏搜索的默认三件套 | 低（这是最优解） |
| 代码块没有语言标识、没有复制按钮 | 中 |
| 大量 emoji 当章节前缀 | 高 |
| 「概述 / 快速开始 / 核心概念 / 最佳实践」的通用目录 | 中 |

**判据重点**：**内容是否回答真实问题。** 文档站的结构问题不是 AI 味的主要来源，内容空转才是。目录里有没有「常见错误」「为什么不生效」「这算不算 bug」这类真实问题？

**优先级**：
1. L2 — 补真实问题型文档（从 issue / 客服记录里捞）
2. L1 — 删 emoji 前缀，代码块补语言标识与复制
3. L3 — 很少需要动

---

## 7. 通用：什么情况下**完全不要动**

- 内部一次性工具、给一个人用的脚本
- 已经上线且用户没抱怨的管理后台（改动风险 > 收益）
- 有设计师在维护的项目（应由设计系统解决，不是由这个 skill 解决）
- 用户的实际诉求是「性能」「无障碍」「转化率」——那些有更直接的手段，别绕道配色

---

## 8. 场景判定速查

```
这个页面给谁看？
├─ 陌生人第一次看（落地页/官网/作品集）
│    → L3 优先：结构与非默认决定
├─ 熟手每天用（后台/工具）
│    → L2 优先：默认值、口径说明、信息密度
├─ 手机用户（移动端/小程序）
│    → L2 优先：图标体系、平台习惯
└─ 开发者读（文档）
     → L2 优先：内容真实性，视觉其次
```
